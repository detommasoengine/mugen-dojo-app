## 1. Che cos'è MugenDojo

Applicazione cross-platform (Android + WebApp) per la **gestione interna di un Dojo di Aikido**. Il sistema traccia presenze, ore di pratica, gradi (Kyu/Dan), risorse di studio, comunicazioni e progetti interni del Dojo.

**Utenti target:**
- **Aikidoka** (studenti) → usano l'app mobile
- **Caposcuola** (admin principale) → usa la dashboard web
- **Segretari** (admin secondari con permessi granulari) → usano la dashboard web

## 3. Regole business chiave

### Anno accademico
1 Settembre → 31 Luglio. Agosto = sospensione. Lezioni regolari: Lun/Mer/Ven 19:00–20:00.

### Formula ore pesate
```
weighted_hours = effective_hours × event_weight × role_weight
```
- `event_weight`: configurabile per evento (default 1.0, stage possono pesare diversamente)
- `role_weight`: partecipante = 1.0, conduttore (Senpai autorizzato) = `dojo.conductor_weight` (default 2.0)

### Multi-tenancy
Ogni tabella ha `dojo_id`. Le RLS policy isolano i dati per Dojo. Un utente può appartenere a più Dojo (UNIQUE su `user_id, dojo_id` in profiles).

### Permessi segretario
13 flag booleani indipendenti in `secretary_permissions`: `can_manage_users`, `can_manage_calendar`, `can_confirm_attendance`, `can_view_all_attendance`, `can_send_communications`, ecc. Tutti default `false`, abilitati dal Caposcuola.

### RLS — Pattern standard (dopo migration 010)

Ogni policy usa **esclusivamente** le 3 funzioni SECURITY DEFINER:
```sql
-- Membership check (12 occorrenze)
dojo_id IN (SELECT get_user_dojo_ids())

-- Profile ownership (8 occorrenze)
profile_id IN (SELECT get_user_profile_ids())

-- Admin check (15+ occorrenze)
is_head_master_of(dojo_id)
```
**Zero subquery dirette su `profiles`** nelle policy. Il trigger `prevent_self_escalation` impedisce auto-modifica di role/grade/can_conduct.

## 8. Problemi noti e risolti

| Problema | Causa | Soluzione |
|----------|-------|-----------|
| RLS infinite recursion su profiles | Policy self-referenziale (subquery su stessa tabella) | Migration 010 con SECURITY DEFINER helpers |
| `pnpm` non trovato | Pacchetto npm `node` globale sovrascriveva system Node | `npm uninstall -g node` |
| `supabase` CLI non nel PATH | npm blocca install globale di supabase | Usa `npx --yes supabase@latest` negli script |
| Expo `tsconfig.base` not found | pnpm strict isolation non crea symlink nei workspace | `.npmrc` con `node-linker=hoisted` |
| VSCode errore TS persistente | Cache server TypeScript | `Ctrl+Shift+P` → "TypeScript: Restart TS Server" |

## 9. Convenzioni critiche

- **Lingua**: UI in italiano, codice/commenti in inglese
- **Commit**: Conventional Commits — `type(scope): description`. Scopes: mobile, admin, shared, supabase, docs, root
- **DB naming**: snake_case inglese (tabelle, colonne, policy)
- **Migration**: `YYYYMMDD_NNN_descrizione.sql` — mai modificare migration committate, creare nuove
- **RLS**: sempre attivo, ogni tabella. Usare i 3 helper SECURITY DEFINER, mai subquery dirette su profiles
- **Commit progressivi**: ogni blocco logico ha il suo commit, vietati commit monolitici
- **Package manager**: pnpm (non npm, non yarn)
- **Segreti**: mai in git — `.env.local` per le chiavi
